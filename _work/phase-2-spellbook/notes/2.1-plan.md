# 2.1 — `/plan`, the first three-way split

**Date:** 2026-08-03
**Gate:** 8/8 (check 8 is new — see below)
**Sizes:** 225 source → 275 L0 + 89 L1. Slots: 4 in L0, 2 in L1.

Re-measured first: 225 / 205 / 114, unchanged. The two versions turned out to be
*structurally identical* — same seven steps, same headings — so the 114 diff lines were all
within-section drift. That made the seam map cheap to read: `diff` on headings first, then both
files.

## ADR 0003 — how L0 reaches L1

The real decision of this increment. The source interleaves a generic planning engine with two
substantial stack-specific blocks: six MCP tool names for live schema inspection, and a nine-row
table routing extension types to authoritative skills. L0 has to *use* that guidance when
present and work without it when absent — but two principles forbid the obvious approaches. L0
can't name the pack (technology fact in core), and can't invoke it (chain by suggestion, never
invocation).

Resolution: **packs contribute model-invoked reference skills with trigger-engineered
descriptions; L0 describes the *kind* of guidance it wants and lets skill discovery route.** L0
`/plan` asks for "live state inspection", "sub-type routing", and "typical step order" — never
for Umbraco. The pack's `umbraco-17-planning` description does the matching.

Same property the slot mechanism gives project facts, one layer up: additive when present,
invisible when absent. And adding `optimizely` later costs nothing in core.

The cost is real and worth naming: **a pack skill with a weak description fails silently**, and
the symptom is a merely-generic plan rather than an error. Pack descriptions need the same
trigger-engineering rigor as core references.

## One slot, one point of authority — applied twice

Phase 1's rule immediately earned its place:

- **Build and test commands.** Both `/plan` and `/implement-step` need them, so who owns the
  slot? `/plan` does — because the plan artifact *records* the command in every step's Validation
  block, and `/implement-step` reads the plan. The artifact is the carrier, so the second spell
  needs no slot reference at all. This is how the source already worked; the rule just made it
  visible.
- **Branch naming.** `/spec` owns it (it creates the branch). `/plan` only records the branch in
  the plan header, so it reads `git branch --show-current` instead of re-declaring the slot.

Two spells that naively looked like they needed four slot references between them need one, held
by whichever spell actually decides the fact.

## Check 8: no technology names in L0

ADR 0003's discipline is only real if it's enforced, so the gate now greps `skills/core/` for a
list of technology names. It caught a leak on first run — the `workflow` skill said "front-end or
**backoffice** tweaks", CMS vocabulary inherited from the source where it read naturally.
Generalized to "admin-UI".

That is the third time an automated check has caught something a careful read had already passed
over. L1 packs are exempt by design — naming their technology is their job.

## Wrote L1 fully rather than stubbing it

The plan called for an L1 stub filled in at 5.5. Wrote it complete instead: the source content
was already in context, and deferring would mean re-reading a 225-line file later purely to
recover what I'd just read. 5.5 now only needs the reviewer rule sections plus a verification
pass.

## Judgment calls

- **Step 3's layer table became a checklist.** The source's table was entirely stack-specific
  (columns for `.uda` paths, RCL globs, Vite manifests). The generic version keeps the *kinds* of
  layer — schema, server-side, client-side, extension surface, tests — with the constraint that
  matters for each, and defers vocabulary to the project and any pack. Some concreteness is
  genuinely lost here; the pack restores it.
- **Kept "Schema first" as a generic rule.** It reads stack-flavored but the underlying claim is
  universal: nothing compiles against types that don't exist.
- **`/plan`'s Step 6 gained a slot** for project-specific planning gotchas, replacing the
  source's hardcoded embedded-resource-glob check. Its fallback explicitly says *don't invent
  constraints* — the failure mode for that slot is a confidently fabricated rule.
