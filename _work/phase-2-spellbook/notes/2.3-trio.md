# 2.3 — `/implement-step`, `/code-review`, `/commit-message`

**Date:** 2026-08-03
**Gate:** 8/8. Preservation: 11/11, 13/13, 4/4.
**Sizes:** 119 + 51 + 44 = 214 source → 158 + 84 + 55 = 297. Slots: 1 + 1 + 2.

Bundled because they are one identical file and two near-twins. `/implement-step` had **zero** diff
lines between repos, so it read once.

## Two de-projections worth recording

**A reviewer named after a CMS.** The source's three reviewers are `accessibility-reviewer`,
`perf-reviewer`, and `umbraco-code-reviewer`. The third cannot ship in core under ADR 0003 — it is
a technology name in an L0 file, and check 8 would reject it. Renamed to **`code-reviewer`**. The
pack adds *rules* to that reviewer (increment 5.5), it does not rename it, which keeps a project
from ending up with two quality reviewers when a pack is installed.

**Emoji commit types are a project convention, not a toolkit opinion.** The source hardcodes seven
emoji-prefixed types and a fixed trailer block. Shipping that would impose one team's convention on
every consumer — plenty of projects use plain imperative subjects, ticket prefixes, or their own
scheme. Now two slots (`## Commit format`, `## Commit trailers`) whose fallback is to **infer from
`git log`** rather than assert a default, with an explicit instruction not to introduce a trailer
convention the project hasn't adopted. This is the clearest case so far of extraction finding a
project fact that was invisible while it sat in the project.

## One deliberate improvement

The source gave the three reviewers **different severity scales** — Blocker/Major/Minor/Nit for two
of them, Critical/High/Medium/Low/Info for the performance reviewer. But `/code-review`'s whole job
is merging them into one report with one ordered action plan, and two scales make that ordering
ambiguous.

Normalized all three to **Blocker/Major/Minor/Nit**, and added a merge rule the source lacked: when
two reviewers disagree on severity, take the higher and note the disagreement, because it usually
means the issue has two distinct costs. This does drop the performance reviewer from five levels to
four; the ranking coherence is worth more than the extra gradation.

## Claude-specific surfaces, handled per the known lock-in edge

`/implement-step` dispatches a worker and `/code-review` dispatches three. Both are Claude-specific.
Per the direction doc's accepted position — Claude-opinionated is fine, document the edge — each now
carries an explicit degradation: `/implement-step`'s worker prompt is *designed* to be pasteable by
hand (which is why it must be self-contained anyway), and `/code-review` falls back to running the
three passes inline under the same scale and merge rules. Neither degradation changes the contract,
only the convenience.

## Method lesson: probe with anchors, not sentences

Four probes flagged LOST across the two smaller files; all four were rewordings — "not just what"
became "not merely what", "Show summary of changes currently staged" became "Show a summary of what
is currently staged". Nothing was lost.

The tool checks verbatim survival, but de-projecting legitimately rewords prose. Probing with whole
source sentences therefore generates false alarms, and false alarms are worse than no check because
they train you to wave off the real ones. Now documented in the script: probe with **semantic
anchors** — distinctive terms, literal values, severity labels, output-format keys — and treat LOST
as "go read the file", never as "content was dropped".

Two method corrections in two increments, both in the verification half rather than the extraction
half. Worth watching whether that keeps happening.
