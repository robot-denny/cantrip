# 2.5 — `/retrofit`, and the check that found four latent bugs

**Date:** 2026-08-03
**Gate:** 9/9 (check 9 is new). Preservation: 17/17.
**Sizes:** client 154 + demo 120 → 232 L0. Slots: 2.

## A real best-of-both, not a superset pick

Unlike `/feature`, neither version dominated here. The heading map made it look like the client was a
clean superset — it has the operating-mode preamble, the apply step, and the Rules section the demo
lacks — but reading the demo's unique lines found substantial content the client is missing:

| From the demo | Why it matters |
|---|---|
| **Resolve the base branch from the upstream tracking branch** | A genuine bug fix. A local default branch is often stale, which inflates the diff with everything the local copy is missing and mis-scopes the whole retrofit. The client version just says "usually master". |
| **Empty-diff guard** | The client version has no "nothing to retrofit" exit at all. |
| **Explicit range/ref argument** | Lets the developer scope it directly rather than relying on auto-detection. |
| **Reconciliation table** with ✅/⚠️/❌ | More actionable than the client's prose bullets, and the worked example teaches the format. |
| **Description-optional handling** | Falls back to inferring intent from commit messages and states which source it used. The client just says "proceeding from the diff alone". |
| **When to run it** | Before commit ideally; before push if already committed; run it even when the change feels too small. |

Had I trusted the structural map and skipped reading the demo's diff, all six would have been lost —
including the base-branch bug. Worth remembering that "structurally a superset" and "content-wise a
superset" are different claims.

## Check 9 found four latent bugs, two of them mine

Writing `/retrofit` forced a question the contract hadn't answered: `/plan` owns the
`stack.md → ## Build` slot, but retrofit genuinely needs it too and has no plan to inherit it from.

So I refined the rule: **it governs the fact, not the reference.** Multiple independent consumers of
one slot are fine. What must never happen is two files declaring *different fallbacks* for the same
slot — that is silent behavioral divergence whenever the slot is empty, and it is worse than plain
duplication because nothing looks wrong until the moment it matters.

Then I made that mechanically checkable, and check 9 immediately failed on **four** slots:

| Slot | Consumers | Divergence |
|---|---|---|
| `paths.md → ## Code layout` | `/plan`, `/feature` | Different inference strategies entirely |
| `paths.md → ## Umbraco` | both pack skills | Each located a *different subset* of paths |
| `stack.md → ## Models` | both pack skills | Same inference, different conclusions drawn |
| `stack.md → ## Build` | `/plan`, `/retrofit` | "say which you used" vs "state which you used" |

Three of these predate this increment and had already passed the gate at 2.1 and 2.2 — I even flagged
the `## Umbraco` one in the 2.2 note as "revisit at 5.5" without recognizing it as a defect rather
than an untidiness.

The `## Umbraco` case carried a design insight: the two skills' fallbacks located different things
because the *slot heading was too coarse* for what its readers actually wanted. Where two consumers
want genuinely different inference from one slot, that is the signal to either unify what the slot
covers or split the heading. I unified — the canonical fallback now locates all three Umbraco
locations, and each skill's specific consequence moved to prose after the block.

That pattern — the fallback states the inference, prose after it states the consumer-specific
consequence — is what keeps the fallbacks identical while letting the spells differ.

## Method note

Fourth increment, fourth gate improvement, and this is the first check that found bugs in *previously
approved* work rather than in the increment being written. The pattern across 2.1–2.5 is that each
new contract rule needs a check written at the same time, or it silently doesn't hold — the rule
alone was in `docs/contract.md` since Phase 1 and had been violated three times before becoming
enforceable.
